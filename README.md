# 하나씩 · 할 일

마감일과 우선순위로 정렬되는 개인용 체크리스트. 서버, 로그인, 유료 서비스, 별도 빌드 없이 사용할 수 있습니다.

## 사용

- 할 일을 입력하고 Enter를 눌러 추가합니다.
- 마감일 오름차순 → 우선순위 높음/보통/낮음 → 등록 순서로 정렬합니다. 기한이 없는 항목은 뒤로, 완료한 항목은 아래로 이동합니다.
- 각 항목의 연필 버튼으로 수정합니다. 삭제 직후 7초 동안 되돌릴 수 있습니다.
- '백업 · 불러오기'에서 JSON 백업을 저장하거나 기존 목록에 합칠 수 있습니다.
- 목록은 현재 사이트 주소와 브라우저의 localStorage에 저장됩니다. 다른 브라우저나 기기와 자동으로 동기화되지 않습니다. 주소가 바뀌기 전에는 백업하고 새 주소에서 불러오세요.

## GitHub Pages에 배포

1. GitHub에서 새 **공개 저장소**를 만듭니다. 예: `hana-todo`.
2. 이 폴더의 파일을 저장소 최상위에 업로드합니다. `index.html`이 저장소 최상위에 있어야 합니다.
3. 저장소 **Settings → Pages → Build and deployment**에서 **Deploy from a branch**, **main**, **/(root)**를 선택하고 저장합니다.
4. 배포가 끝나면 Pages 화면에 표시되는 HTTPS 주소로 접속합니다.

앱 코드는 공개됩니다. 실제 할 일은 브라우저에 저장되므로 저장소에 올라가지 않습니다. 개인 백업 파일을 저장소에 업로드하지 마세요.

## 앱으로 설치

- Mac Safari: 사이트를 열고 **파일 → Dock에 추가**.
- Chrome / Edge: 설치 아이콘 또는 메뉴의 앱 설치 기능을 사용합니다.
- 첫 온라인 접속 후에는 오프라인에서도 사용할 수 있습니다. 브라우저의 캐시/사이트 데이터를 삭제하면 오프라인 파일 또는 목록도 삭제될 수 있습니다.

## 로컬 미리보기

이 폴더에서 `python3 -m http.server 4173 --bind 127.0.0.1`을 실행한 뒤 `http://127.0.0.1:4173`을 엽니다. 로컬 주소와 배포 주소는 목록을 각각 저장합니다.

## 구성

`index.html`, `style.css`, `app.js`: 앱 화면과 동작. `manifest.webmanifest`, `sw.js`, 아이콘: 설치 및 오프라인 지원.

앱 파일을 업데이트할 때는 `sw.js`의 CACHE 버전도 올리면 이전 오프라인 캐시가 정리됩니다.
